# landing-builder 개선 기록과 재현 방법

이 스킬은 한 번에 완성되는 물건이 아니라 실제 사용 → 결함 발견 → 반영을 반복해 다듬는다.
다음 세션에서 이어서 개선할 수 있도록 지금까지의 근거와 재현 절차를 남긴다.

## 어떻게 검증하나

`evals.json`에 테스트 요청 2개와 채점 기준이 들어 있다. 검증은 이렇게 한다:

1. 각 요청을 **스킬을 읽은 에이전트**와 **스킬 없는 에이전트**에게 각각 시킨다
2. 두 결과물을 `evals.json`의 `assertions`로 채점한다 (근거를 함께 남긴다)
3. 결과물을 iframe으로 나란히 띄운 비교 페이지를 만들어 사람이 눈으로 본다 —
   채점표는 사실 오류를 잡지만 "인상이 유형답게 나왔는가"는 사람만 판단할 수 있다

스킬 없는 쪽을 함께 돌리는 이유: 통과율이 높아도 스킬 없이도 그만큼 나온다면
그 항목은 스킬의 가치를 증명하지 못한다. 실제로 카페 케이스는 양쪽 5/5였다.

## 1차 결과 (2026-09)

| 케이스 | 스킬 사용 | 스킬 없음 |
|---|---|---|
| 모루커피 · 차분한 카페 (사진 없음) | 5/5 | 5/5 |
| 미닛츠 · SaaS 무료체험 전환 | 5/5 | 2/5 |

스킬 없는 SaaS 산출물의 실패 3건:
- 프롬프트에 **로고로만** 언급된 고객사에 실명 인물 후기와 별점을 창작, "30초·전환율 4%" 등 수치도 창작
- IntersectionObserver가 없어 스크롤 등장 효과가 아예 부재
- 수치 밴드가 기능 설명보다 앞에 나와 설득 순서가 뒤집힘

비용: 스킬 사용 시 평균 토큰 +28,297, 시간 +98초.

## 1차 이후 반영한 것

채점표가 잡지 못했지만 결과물을 직접 보고 발견한 결함들:

- **단일 파일 요구 무시** — 두 프롬프트 모두 "index.html 하나로"라고 했는데 `assets/` 2개 파일에
  의존해서, index.html만 열면 스타일도 인터랙션도 없었다 → 단일 파일 요청 시 인라인하도록 명시
- **CTA에 도착지 없음** — 전환이 목표인데 최종 CTA가 `href="#"`였다 → 실제 도착지나 최소 신청 폼 필수
- **히어로 우측 공백** — 유형 3 히어로가 좌측 텍스트만이라 데스크톱에서 미완성으로 보였다
  → 이미지 없으면 CSS 목업/SVG로 채우도록 규칙 추가
