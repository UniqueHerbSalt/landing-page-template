# Landing Builder — 6유형 브랜딩 랜딩페이지 제작

유명 브랜드 랜딩 30개를 분석해 도출한 6가지 유형(archetype) 중 하나를 골라,
번들된 인터랙션 키트 위에 유형별 디자인 언어를 입혀 **단일 정적 HTML 랜딩페이지**를 만든다.

핵심 철학: 랜딩이 밋밋해지는 원인은 대부분 "유형 없이 섞어 짓기"다. 유형을 하나 고르면
팔레트·타이포·섹션 순서·모션 문법이 함께 결정되고, 페이지에 일관된 인상이 생긴다.
**액센트는 반드시 한 색**, 나머지는 그라운드와 텍스트 스케일이 담당한다.

## 워크플로우

### 1. 콘텐츠 파악
브랜드/인물의 실제 데이터를 먼저 모은다: 이름·한 줄 정체성, 증명 가능한 숫자(연차·건수·평점·고객 수),
대표 작업/제품 3~9개, 신뢰 요소(협업사·수상·언론), 연락 수단. 이미지가 있으면 로컬 경로로 받고,
없으면 이미지 없이도 성립하는 유형(3·4·5)을 우선 검토한다.
숫자가 없는데 지어내면 안 된다 — 없으면 숫자 밴드 자체를 빼는 게 낫다.

### 2. 유형 선택
아래 표로 추천하되, 사용자의 무드 표현("힙하게", "차분하게", "신뢰감")을 우선 신호로 삼는다.
애매하면 후보 2~3개를 한 줄 설명과 함께 제시하고 고르게 한다.

| # | 유형 | 이런 요청에 | 참고 브랜드 |
|---|---|---|---|
| 1 | 임팩트 캠페인형 | 강렬하게, 힙하게, 스포티하게, MZ | Nike · Gentle Monster · Red Bull · 무신사 |
| 2 | 프로덕트 몰입형 | 제품/작품이 주인공, 미니멀 프리미엄 | Apple · Tesla · 현대카드 |
| 3 | 전환형 SaaS | 가입·상담·구매 전환이 목표 | Stripe · 토스 · Notion · Linear |
| 4 | 헤리티지 내러티브형 | 신뢰감, 기업/기관, 역사와 스토리 | 신도리코 · 네이버 · 카카오 |
| 5 | 콰이어트 에디토리얼형 | 차분하게, 감성적으로, 글이 좋은 브랜드 | Aesop · 무인양품 · Anthropic |
| 6 | 커머스 큐레이션형 | 상품/프로그램 여러 개를 골라 담게 | Airbnb · IKEA · 29CM |

유형이 정해지면 **`references/archetypes.md`에서 해당 유형 섹션을 반드시 읽는다** —
팔레트 공식, 섹션 골격 순서, 타이포 스케일, 모션 문법, 흔한 실수가 유형별로 정리돼 있다.

### 3. 키트 세팅
`assets/shared.css`와 `assets/fx.js`를 프로젝트에 복사한다(수정하지 말고 그대로).

**사용자가 "파일 하나로", "index.html 하나만", "단일 파일로"라고 했다면 복사 대신 인라인한다** —
shared.css 내용을 `<style>` 맨 앞에, fx.js 내용을 `</body>` 직전 `<script>`에 그대로 넣는다.
`assets/` 참조가 남아 있으면 사용자가 index.html만 열었을 때 스타일도 인터랙션도 없는 빈 문서가 된다.
이건 실제로 흔한 요구이니 프롬프트에서 파일 개수 요구를 먼저 확인하는 습관을 들인다.

shared.css는 구조만 갖고 있고, 페이지의 `<style>`에서 `:root` 토큰을 재정의해 테마를 입힌다:

```css
:root{
  --bg / --surface / --card-bg          /* 그라운드 3단 */
  --text-primary / -secondary / -muted  /* 텍스트 스케일 */
  --border / --accent / --accent-contrast / --accent-light
  --fx-accent / --fx-accent-ink  /* 인터랙션 액센트: 글로우·링·CTA·티커·스파크. fx.js가 런타임에 읽음 */
  --nav-bg / --radius / --font-body / --font-display
}
```

토큰 값은 archetypes.md의 유형별 공식을 따른다. 폰트는 Pretendard(jsdelivr CDN)를 기본으로,
유형 5만 Noto Serif KR(Google Fonts)을 `--font-display`에 추가한다.

### 4. 페이지 조립
archetypes.md의 섹션 골격 순서대로 단일 HTML을 짓는다. 키트가 제공하는 인터랙션:

- **스크롤 리빌**: 등장시킬 블록에 `class="reveal"` — IO가 `.in`을 부여 (goldenrecords.kr 실측 파라미터)
- **스프링 숫자 티커**: `<span class="gr-ticker" data-value="700" data-suffix="+">700+</span>`
  (`data-decimals`, `data-prefix`도 지원. 태그 안에 최종 표시값을 넣어두면 JS 미작동 시 폴백)
- **무한 마퀴**: `.marquee > .marquee-track`(항목 1벌만 작성 — 복제는 JS가 함),
  `style="--mq-dur:45s"`로 속도, `.rev`로 역방향, 호버 시 일시정지
- **카드 호버 5중주**: `.fx-card > .fx-frame > img + .fx-glow + .fx-cta`, 태그는 `.fx-tag`
- **필터 스태거 등장**: 그리드를 다시 그린 뒤 `fxFilterAppear(엘리먼트목록)` 호출
- **스파크 필드**: `<div id="spark-field" aria-hidden="true">`를 body 직하에 두면 액센트색 트윙클 배경
- **스크롤 스파이**: `.nav-links a[href^="#"]`와 섹션 id가 맞으면 자동 동작
- `prefers-reduced-motion: reduce`와 IO 미지원 폴백은 키트가 자동 처리

규칙:
- 모든 경로는 상대 경로 (GitHub Pages 서브패스 서빙 대비)
- 외부 리소스는 폰트 CDN만. 이미지는 로컬, 핫링크 금지
- 모바일 `≤768px` 반응형 규칙을 페이지 CSS에 포함
- **CTA는 반드시 실제 도착지를 갖는다** — `href="#"`로 두면 랜딩의 존재 이유가 사라진다.
  사용자가 준 연락 수단(메일·전화·카톡채널·예약폼 URL·앱스토어)을 연결하고, 전환이 목표인데
  받을 곳이 없으면 이름·연락처·회사만 받는 최소 폼을 페이지 안에 만들고
  제출 시 성공 상태로 바뀌게 한다(백엔드 없이 클라이언트 검증만, 나중에 연결하도록 주석 표시)
- **이미지가 없으면 CSS/SVG로 만든다** — 히어로나 피처 옆이 텅 비면 미완성으로 읽힌다.
  제품이면 CSS만으로 그린 UI 목업(창 프레임 + 텍스트 줄 + 뱃지), 가게·작가면 간결한 인라인 SVG
  라인 드로잉. 스톡 이미지 URL을 넣거나 깨진 `img` 경로를 남기지 않는다
- 카피는 사용자의 실제 데이터로 쓰되, 유형의 목소리로 다시 쓴다(유형 1은 짧고 명령형,
  유형 5는 문장형 — archetypes.md의 카피 톤 참고)

### 5. 검증
`python3 -m http.server`로 띄우고 Playwright(Chromium)로 확인한다:
콘솔 JS 오류 0인지, 리빌·티커·마퀴가 동작하는지, 상·하단 스크린샷으로 유형의 인상이 나오는지.
스크린샷을 사용자에게 보여주고 피드백을 받는다. 여러 유형 비교 요청이면 유형별 파일을
나란히 만들고 허브 페이지로 묶는다.

## 흔한 실수 (전 유형 공통)

- 액센트 2색 이상 → 즉시 싸구려 느낌. 강조가 더 필요하면 색이 아니라 크기·굵기·여백으로
- 유형 골격에 다른 유형 섹션 끼워 넣기(예: 에디토리얼형에 벤토 그리드) → 인상이 무너짐
- 근거 없는 숫자·후기 창작 → 사용자가 준 데이터만. 없으면 해당 섹션 생략
- shared.css를 직접 수정 → 토큰 재정의로 해결이 안 되면 페이지 `<style>`에서 오버라이드
